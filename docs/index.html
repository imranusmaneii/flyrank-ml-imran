Ranking Content Refresh Opportunities from Search & Engagement Signals

An observational ranking study that turns anonymized content-performance signals into a practical review queue—without exposing client identity, URLs, queries, or private search data.

Lane: Refresh / Content Opportunity Scoring30,000 eligible rowsRandom forest selectedPublic-safe analysis

Title + Abstract

Question. Can safe, aggregated search and engagement signals rank existing content for refresh review more effectively than a simple rule-based score?

Method. I filtered the anonymized content-refresh slice to pages with measurable search visibility and sufficient age, defined a decline label from the supplied trend direction, compared a rules baseline with logistic regression, a decision tree, and a random forest, and evaluated them on the same client-holdout split.

Result. The random forest was the strongest tested model, reaching ROC AUC 0.750, average precision 0.618, and Precision@50 of 0.740 versus 0.240 for the rules baseline.

Decision use. The resulting score is best treated as a reviewer-prioritization signal: high-ranked items should be inspected first, not automatically rewritten or published.

Framing. These are measured associations in one anonymized release; they do not prove Google's ranking algorithm, causality, or that a refresh will produce a particular traffic lift.

Introduction / Problem statement

Content teams rarely have enough review capacity to inspect every page with the same depth. The decision supported here is therefore operational: which existing pages deserve attention first? The capstone focuses on prioritization rather than predicting an external Google outcome.

The lane was chosen because the Week 4 baseline already produced an interpretable refresh queue. The capstone extends that work into a model comparison and a ranked action engine while keeping the output public-safe.

The analysis uses the bundled anonymized FlyRank content-refresh slice. Eligible records had positive impressions in the 90-day window and content age of at least 90 days; duplicate content IDs were removed. Client names, domains, titles, URLs, private queries, credentials, and raw external exports are not used in the paper.

Observed fields used as predictors include search demand/competition measures, content length, impressions/clicks/sessions, visibility days, age/freshness, CTR, average position, engagement, scroll behavior, and categorical content/intent/age tiers.

Important data caveat: the available release is a cross-sectional anonymized slice. Because the label is supplied as trend_direction == down, this study evaluates ranking of observed decline risk rather than a clean future-window prediction of decline.

Methodology

Label and baseline

The target is binary: 1 when the supplied trend direction is down, otherwise 0. The baseline is the hand-written refresh score developed earlier in the track. Models tested were logistic regression, a constrained decision tree, and a random forest.

Validation

The reported comparison uses the same client-holdout split for baseline and models. Clients were shuffled with a fixed seed and approximately 20% held out when enough clients were available; a stratified row holdout is the fallback if the client split cannot preserve both classes. This reduces client-level memorization risk, but it is not a time-aware future prediction test.

Leakage controls

Target-derived fields such as the supplied trend direction and trend percentage are not included in the model feature list. The model uses only pre-existing aggregated performance/content signals selected for the feature vector. The final result should still be interpreted as association, because some predictors summarize the same observation window from which the label was derived.

Selection metric

The model is selected by Precision@50, matching the practical question: if a reviewer can inspect only a small top queue, how concentrated are declining pages in that queue?

Limitations & honest framing

  • Association, not causation: the model identifies patterns associated with the supplied decline label; it does not prove that a feature causes ranking movement.
  • No Google-algorithm claim: the study does not infer or reverse-engineer Google's ranking system.
  • Cross-sectional label: a future-window label would be stronger for deployment because it would separate predictors from outcomes in time.
  • Window overlap: many predictors and the label describe the same observed period, so the high ranking performance should not be treated as evidence of prospective accuracy.
  • Single anonymized release: performance may differ on other clients, industries, periods, or content systems.
  • Reviewer-in-the-loop: scores are decision support. Editorial context, search intent, business priorities, and page quality still require human review.

Ranked recommendations

  1. Prioritize high-score, visible pages for manual refresh review. Start with the top queue because the model is optimized for concentration of declining pages near the top.
  2. Inspect CTR before rewriting everything. A repeated top-queue reason is low CTR on pages that still have measurable impressions, making metadata/search-snippet review a sensible first check.
  3. Separate engagement problems from demand problems. Use engagement and scroll signals to decide whether the next action is content-structure improvement rather than only title/meta changes.
  4. Use age and visibility as triage signals, not automatic rewrite triggers. Older, consistently visible content deserves review, but age alone is not evidence that a refresh will work.
  5. Keep the rules baseline as an explainability fallback. The model wins on ranking metrics, while rules remain useful for sanity checks and reviewer communication.
  6. For the next iteration, build a future-window label. This is the highest-value methodological upgrade: features from period T should predict a decline/change outcome in period T+1.
